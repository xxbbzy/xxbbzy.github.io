## 起因：一个看着像 MCP 端点的链接

手里拿到一个 `s.hexin.cn` 的链接，第一反应是：这就是同花顺投资账本的 MCP 地址，照着接就行。

结果不是。

## 排查一：s.hexin.cn 只是个跳转

打开 `https://s.hexin.cn/`，直接 301 跳到同花顺投资账本（`tzzb.10jqka.com.cn`）。又试了 `/mcp`、`/sse`、`/api/mcp` 几个常见 MCP 路径，还发了一个标准的 MCP 握手请求，得到的全是同样的跳转，没有任何 MCP 响应。

结论很干脆：这个域名就是个跳转用的短链域名，本身不是 MCP 端点。MCP 端点不要靠猜路径，先找到服务方给的正式入口。

真正的入口在登录后的页面上：投资账本里有个「AI连接」的入口，账本数据通过 MCP 开放给 AI 客户端的配置就在那里。

## 排查二：动态注册带 scope 就报 400

这套接入走的是 OAuth 2.1，授权服务器支持动态客户端注册，不用事先建应用、不用复制密钥，点授权链接走完登录和确认就行。

但它的客户端注册接口有个怪脾气：**注册请求里只要带了权限范围（scope），就直接报 400 invalid_scope**。换了几种 scope 写法都被拒，只有完全不带 scope 字段的注册才能通过，通过之后授权跳转本身是正常的。

这个 400 很容易误判。报错在客户端侧看起来就是"连接失效"，第一反应往往是链接坏了、过期了，于是反复点链接、反复登录，其实问题根本不在链接，在注册请求里多带的那个字段。

## 两条可以留下的经验

1. **MCP 客户端如果默认总带 scope，遇到这类服务端会一直失败。** 排查时先看注册请求到底发了什么，而不是反复重试授权链接。如果客户端允许配置，注册时把 scope 去掉。
2. **区分"端点不存在"和"注册被拒"。** 前者是地址问题：打开就跳转、没有任何 MCP 响应；后者是协议问题：授权流程能走到注册那一步，是注册本身被服务端拒绝。两种现象修的方向完全不同，混在一起查会浪费很多时间。

另外一个小提醒：接通之后读到的数据新不新，取决于投资账本 PC 端上一次同步的时间，查之前先在电脑上同步一次。
